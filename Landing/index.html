01 / DETECT

Point it at your repo

SAGE reads your dependency manifests — requirements.txt, package.json, pyproject.toml — and maps every library. Nothing assumed, everything read.

02 / MAP

Build a knowledge graph

Synapse uses tree-sitter to walk your AST and build a graph of every file, function, import, and call edge. Your codebase becomes queryable structure.

03 / SIGNAL

CVEs become live graph nodes

NVD CVEs are attached directly to library nodes. You see exactly which functions reach the vulnerable library and the full blast radius — not a flat list.

04 / ANALYZE

AI confirms exploitability

Claude Opus handles CRITICAL findings. Sonnet handles the rest. Only confirmed exploitable paths proceed — zero false alarms sent to PR stage.

05 / PATCH

Patches generated and verified

Dep bumps land in your requirements file. AI-generated code patches fix the call sites. Semgrep runs again post-patch to confirm no regressions.

06 / SHIP

A PR lands in your repo

A timestamped branch is created and a PR raised automatically — with CVE table, patch diffs, test results, and AI rationale. One command. Done.

Quick Start

From zero to first PR in minutes.

Clone, configure keys, point SAGE at any repo.

1
Clone & install
Create a virtual environment and install all dependencies from requirements.txt.
2
Configure keys
Add NVD, Anthropic, and GitHub tokens to .env. Gemini optional.
3
Run the scanner
Point SAGE at any trusted repo. Interactive launcher auto-detects your GitHub remote.
4
Review the PR
SAGE raises a timestamped branch and PR with full CVE table, patch diffs, and AI rationale.
bash
# Clone and set up
$ git clone https://github.com/anubhavmohandas/SAGE
$ cd SAGE
$ python3 -m venv venv && source venv/bin/activate
$ pip install -r requirements.txt

# Configure keys
$ cp .env.example .env
# NVD_API_KEY, ANTHROPIC_API_KEY, GITHUB_TOKEN

# Run (interactive)
$ bash sage_scan.sh

# Or directly
$ python3 main.py --repo /path/to/repo --days 30
$ python3 main.py --synapse /path/to/repo

FAQ

Common Questions

Quick answers to what people ask most.

Is it safe to run SAGE on a production repo?
Yes — SAGE is read-only until the patch stage. It only writes to data/ and your repo if you explicitly confirm the PR. Run with --synapse flag for a graph-only, zero-write mode.
Does Semgrep need to be installed separately?
Semgrep is included in requirements.txt and installs automatically with pip install -r requirements.txt. No separate installation or Semgrep account required.
Can I run SAGE without an Anthropic API key?
Yes — use manual mode. SAGE exports data/prompts/CVE-XXXX.txt for each CVE. Paste into ChatGPT, Claude.ai, Gemini, or any LLM, save the JSON response to data/responses/, then re-run. The pipeline picks up exactly where it left off.
Does SAGE work on JavaScript / Go / Rust projects?
Currently Python-first (requirements.txt, pyproject.toml, Pipfile). JS/TS (package.json) and Go/Rust support are on the near-term roadmap. tree-sitter already supports those grammars — it's a matter of wiring the pipeline.
What if SAGE raises a PR for a false positive?
The AI gating stage is specifically designed to prevent this — SAGE only raises a PR for CVEs where Claude confirms the vulnerable code path is actually reachable and user-controlled input flows to it. In the CyberTrace test, 24 CVEs were found and 0 PRs for exploitable issues were raised — correctly.
How does SAGE get an NVD API key?
Request one free at nvd.nist.gov/developers/request-an-api-key. It's free, instant, and increases your rate limit from 5 to 50 requests/30 seconds. SAGE works without one but will be slower on large repos.
